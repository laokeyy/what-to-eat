App 整体布局结构 — 你更喜欢哪种？

考虑16个功能的组织方式，哪种导航更顺手

A

单页滚动流

所有功能在一个长页面中：顶部开始选 → 中间结果展示 → 底部规则/食谱管理。Tab切换子页面（规则、食谱、历史）。类似抖音的沉浸感，打开就进入"问答流"。

Pros

  • 打开即用，零学习成本
  • 沉浸式体验，减少跳出
  • 适合移动端H5

Cons

  • 功能多时页面拥挤
  • 桌面端利用率低
B

底部Tab导航（移动端优先）

5个Tab：🎲 选饭吃 / 📋 我的食谱 / ⚙️ 规则 / 👤 我的（历史/黑白名单/年度报告）/ 🔮 发现（盲盒/挑战/饭搭子）。类似美团/饿了么的Tab结构。

Pros

  • 功能分区清晰
  • 用户心智模型熟悉
  • 每Tab独立状态管理

Cons

  • "选饭吃"之外的Tab打开率低
  • Tab间切换打断上下文
C

侧边栏 + 主内容区（桌面端优先）

左侧垂直导航栏（折叠/展开），右侧大内容区。适合桌面端 + 响应式适配移动端。主区域始终显示"选饭吃"流程，侧栏快速跳转管理页面。

Pros

  • 桌面端体验最佳
  • 导航不占主区域空间
  • 易于扩展更多功能

Cons

  • 移动端需额外适配
  • 初版开发量大
D

混合：主流程全屏 + 抽屉式侧菜单

核心"选饭吃"流程全屏沉浸式，其他功能（规则/食谱/历史/设置）通过左上角汉堡菜单打开Drawer抽屉。桌面端Drawer常驻为侧边栏。

Pros

  • 主流程不被干扰
  • 桌面/移动端自然适配
  • 功能可达性好

Cons

  • 功能发现性略低
  • 抽屉嵌套层级需注意
